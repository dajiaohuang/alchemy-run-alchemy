Archil gives you disks that mount anywhere in about 100 ms, and sandboxes
to run code next to them. Hot data sits on SSD and the rest in object
storage, either Archil's or your own bucket.

```typescript
// src/Api.ts
import * as Archil from "@alchemy.run/archil";
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/http/HttpServerRequest";
import * as HttpServerResponse from "effect/http/HttpServerResponse";

export const Files = Archil.Disk("Files", {});
export const Box = Archil.Sandbox("Box", {});

export default class Api extends Archil.Service<Api>()(
  "Api",
  { sandbox: Box, main: import.meta.url, port: 3000 },
  Effect.gen(function* () {
    const files = yield* Archil.ReadWriteDisk(Files);
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const key = new URL(request.url, "http://api").pathname.slice(1);
        const text = yield* files.getText(key);
        return HttpServerResponse.text(text);
      }).pipe(Effect.orDie),
    };
  }).pipe(Effect.provide(Archil.ReadWriteDiskHttp)),
) {}
```

The service runs in the sandbox at a public `https://` URL, and reads the
disk with its own S3 user on that disk.

## Out of scope

- Billing (`getBillingUsage`, `getBillingSummary`,
  `getBillingSubscription`): billing objects, not infrastructure.
- A workflow engine: Archil has no durable execution engine.
- Event sources: Archil has no webhooks, notifications, or streams.
- Custom domains: every service is served from its own `archil.app`
  hostname.
